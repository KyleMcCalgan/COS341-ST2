A suitable constructed typeOf(NODE, Γ) reads the syntax node and the current symbol table Γ; numeric literals return n, text literals return t, variables use lookup(Γ,name), and compound nodes recurse.

typeOf(number, Γ) = n
typeOf("text", Γ) = t
typeOf(VAR, Γ) = lookup(Γ,VAR)
assignment(VAR, VAL):
    t = typeOf(VAL, Γ)
    if VAR untyped: bind(VAR,t)
    else if lookup(VAR) != t: error e
if B then S1 else S2:
    check B is Boolean
    analyze S1 and S2 in separate environments
    if types disagree at join: e

3. Fully expanded syntax tree and analysis

SEQ
├── INSTR: x = 7
│   └── VAL: number(7) [n]
└── SEQ
    └── INSTR: if B then SEQ else SEQ
        ├── B: x > 0 [c; bool condition]
        │   ├── VAR x [n]
        │   └── VAL number(0) [n]
        ├── THEN SEQ
        │   └── INSTR: y = 1 [y:n]
        │       └── VAL number(1) [n]
        └── ELSE SEQ
            └── INSTR: y = "hello" [y:t]
                └── VAL "hello" [t]

JOIN: then y:n ≠ else y:t
      ⇒ e (type error)

Procedure you can reproduce in an exam

  1. Expand SEQ until you have every INSTR leaf.
  2. Use the listed grammar production for each node; do not invent a different grammar.
  3. Type the number and string leaves.
  4. Pass the symbol environment into children, synthesize types upward.
  5. Check condition compatibility.
  6. Analyze then and else with separate branch environments.
  7. At their join, annotate the incompatible y types and propagate the error.
Important: the printout has several sequence productions but shows only the meaningful source fragments in the photo. The pedagogical tree above focuses on the source statements, with SEQ recursion made explicit. The branch order does not change the mismatch.
