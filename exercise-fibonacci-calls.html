3. Worked code and full explanation

Caller - source mapping

v0 := 17
PARAM v0
t0 := CALL f, 1
v1 := t0

Callee - intended corrected Fibonacci control flow

FUNCTION f(p1)
Lstart:
  IF p1 == 0 GOTO Lzero
  IF p1 == 1 GOTO Lone
  GOTO Lrecur
Lzero:
  rf := 0
  GOTO Ldone
Lone:
  rf := 1
  GOTO Ldone
Lrecur:
  t1 := p1 - 1
  PARAM t1
  t2 := CALL f, 1
  v2 := t2
  t3 := p1 - 2
  PARAM t3
  t4 := CALL f, 1
  v3 := t4
  rf := v2 + v3
Ldone:
  RETURN rf

Where Chapter 9 fits

For every CALL f, a fresh activation record is established. Each invocation has its own argument p1, local slots v2/v3, return location/context, and return address. The caller saves live caller-saved registers as required, passes the argument, calls; the callee prologue establishes its frame, body computes, epilogue restores state, then returns.

Critical dangling-else issue in the original

if n == 0 then c = 0;
if n == 1 then c = 1;
else {
  a = fibo(n - 1);
  b = fibo(n - 2);
  c = a + b;
}

Because the else attaches to the second if, when n=0 the program assigns c=0 and subsequently enters the else, calling fibo(-1). Thus the printed code is not the terminating standard Fibonacci algorithm. All code above is a clearly identified correction of the apparent intended algorithm.

  7. Check branch fall-through and dangling-else association.
